# «Снабженец» — архитектура

Версия 1 · 08.11.2026 · автор: CTO-план для MVP к защите

## 0. Главные решения (кратко)

| # | Решение | Почему |
|---|---|---|
| 1 | **Новый репозиторий `snabzhenets`, а не форк A2A Маркет.** Нужные модули переносим копированием, с файлом NOTICE об авторстве | 70% кода A2A — двусторонняя сделка (мандаты, торг, песочницы, заказ, УПД). Форк потащит эту сложность и чужую модель данных |
| 2 | **Стек тот же:** FastAPI + SQLAlchemy + Alembic + PostgreSQL 16 (pgvector) + Redis + arq; React 18 + Ant Design + Vite | Код и CI переносятся без переделки; стек знаком |
| 3 | **Агент — это конвейер с состояниями, а не свободный LLM-цикл.** Шаги — обычный код; модель вызывается только в узких шагах со схемой ответа | Предсказуемость и проверяемость: этого требует методика и ждёт жюри. Принцип A2A «деньги считает код» сохраняется |
| 4 | **Все внешние системы спрятаны за портами** (ЕИС, реестр компаний, РНП, почта, сайты, LLM). У каждого порта есть боевая реализация и реализация «демо/запись» | Демо на защите работает офлайн и детерминированно; боевые интеграции подключаются без правки логики |
| 5 | **Демо-режим жёстко запрещает письма реальным компаниям.** Реальные поставщики находятся по ЕИС, но письма уходят их «двойникам» в песочнице, и отвечает симулятор | Этика и честность: так и написано в паспорте |
| 6 | **Каждая цена — с доказательством.** Нет доказательства — цена не попадает в расчёт | Ключевая новизна из паспорта |
| 7 | **Журнал с цепочкой хешей переносим из A2A**, хеш доказательства пишется в журнал | Защита от подмены, повторное использование своей технологии |

## 2. Конвейер «заявка → обоснование» (машина состояний)

```
DRAFT ──разбор──▶ SPEC_REVIEW ──✋ человек подтвердил──▶ SOURCING ──▶ COLLECTING ──▶ ANALYSIS ──▶ JUSTIFICATION_REVIEW ──✋ утвердил──▶ APPROVED ──▶ CLOSED
                     ▲                                       │            │  ▲            │                  │
                     └──── правка спецификации ◀─────────────┘            │  └─ мало цен: расширить список (≤2 раза)
                                                                          └── срок вышел ──▶ ANALYSIS                 └── вернуть на сбор
 Из любого состояния: NEEDS_HUMAN (эскалация с причиной) · CANCELLED
```

| Состояние | Что делает система | Выход |
|---|---|---|
| DRAFT | LLM-разбор текста в позиции (модуль A2A `parse`), поиск пробелов кодом, подбор кода КТРУ | черновик спецификации + вопросы |
| SPEC_REVIEW | ждёт человека: правка позиций, выбор КТРУ | ✋ подтверждено |
| SOURCING | поиск поставщиков по ЕИС (контракты с этим КТРУ/ОКПД2, регион, 3 года) + демо-каталог; обогащение (ЕГРЮЛ); проверки (РНП, аффилированность); выбор 5–10 | список кандидатов с вердиктами |
| COLLECTING | параллельно: (а) сбор цен с сайтов → доказательства; (б) исходящие запросы (outbox) → напоминания по таймеру; (в) входящие письма → разбор | цены по позициям |
| ANALYSIS | проверки методики (код), нормализация НДС и доставки, коэффициент вариации; при нехватке цен — расширение списка | матрица цен с вердиктами |
| JUSTIFICATION_REVIEW | расчёт НМЦК (код), генерация DOCX | ✋ утверждено |
| APPROVED → CLOSED | (опционально) уведомление ответившим поставщикам о публикации закупки | — |

**Механика.** Переход — задача arq `advance(procurement_id)`. Она идемпотентна: ключ — (заявка, шаг, попытка). Состояние меняется в одной транзакции с записью в журнал. Таймеры (напоминания, срок сбора) — cron-задача воркера по образцу `timers.py` из A2A. Для демо есть кнопка «Ускорить время».

**Письма — через outbox.** В транзакции шага пишется строка `outbound_message(status=queued)`. Отдельная задача отправляет её и ставит `sent`. Повторная отправка исключена, сбой SMTP не ломает шаг.

## 3. Модули backend

```
backend/app/
  core/          config, db, security, auth (роли)             ← A2A auth/, security.py
  ai/            gateway/, prompts/, injection.py, pii          ← A2A agents/ml/gateway, injection.py — как есть
  spec/          разбор заявки, пробелы, КТРУ                   ← A2A agents/ml/parse — как есть + новый ktru.py
  suppliers/     discovery, enrichment, checks, router          — новое
  outreach/      шаблоны писем (Jinja), outbox, mailer, inbox, reminders, вопросы поставщиков — новое
  quotes/        разбор письма, вложений (xlsx/pdf), сбор цен с сайтов, нормализация
                                                                ← A2A email_offer.py, price_columns.py + новое
  evidence/      хранилище доказательств (по sha256), снимки страниц — новое
  methodology/   правила М-01…М-09, расчёт НМЦК, профиль параметров
                                                                ← паттерн A2A rules/engine.py (Verdict, worst)
  documents/     DOCX «Обоснование НМЦК» (python-docx)          — новое (шрифты DejaVu из A2A — для PDF)
  journal/       журнал с цепочкой хешей + триггер append-only  ← A2A journal/ — адаптировать поля
  pipeline/      машина состояний, задачи arq, таймеры          ← паттерн A2A timers.py
  integrations/  eis/ registry/ rnp/ mail/ web/ — порт + боевая реализация + fake/replay
                                                                ← A2A scrape/polite.py → web/polite.py
  demo/          симулятор поставщиков, демо-магазин, сценарий  ← A2A ml_catalog (генератор каталога), eval/email (письма-ловушки)
```

**Правило зависимостей:** `ai/` и `integrations/` не знают о доменной модели. Домен (`spec`, `suppliers`, `outreach`, `quotes`, `methodology`) зависит от портов, а не от реализаций. Реализация выбирается в `core/config` через переменные окружения.

## 5. Где работает модель, а где код

| Шаг | LLM | Код (проверка или расчёт) |
|---|---|---|
| Разбор заявки | `parse_positions`, `parse_meta` (A2A, eval 98–99%) | восстановление артикулов, единиц, пропущенных строк (A2A `postprocess`) |
| Код КТРУ | выбор из top-k кандидатов, найденных поиском по справочнику (bge-m3) | поиск top-k; человек подтверждает |
| Совпадение товара на странице | «тот ли это товар» (да/нет + причины) | цена — **только из разметки schema.org/JSON-LD**; запасной путь — LLM, но число обязано буквально найтись в тексте страницы |
| Ответ поставщика (письмо) | `parse_email_offer` (A2A) | сверка каждого числа с текстом письма, НДС по белому списку, «цена за единицу» (A2A `verify`) |
| Вложение Excel | `map_columns` (A2A `price_columns`) | разбор колонок, числа, единицы |
| Вложение PDF | текст через pdfplumber → тот же `parse_email_offer` | та же сверка |
| Вопрос поставщика | классификация: на что можно ответить из спецификации | ответ собирается шаблоном **только из полей спецификации**; остальное — человеку |
| Исходящие письма | **нет** | шаблоны Jinja: юридически значимый текст не генерируется |
| Проверки методики, НМЦК, CV | **нет** | только код, `Decimal` |

Все вызовы — через шлюз A2A: схема ответа, один переспрос, переход на резервного провайдера, `AgentNotSure` → эскалация к человеку. Внешний текст оборачивается в `<data>` и проверяется фильтром инъекций (A2A `injection.py`).

## 6. Методика (движок правил)

Профиль `methodology/profiles/mer567_v1.yaml` хранит параметры с источником: `min_requests: 5`, `min_prices: 3`, `max_age_days: 180`, `cv_max: 0.33`. Вердикты — как в A2A: `ALLOW / WARN / HUMAN / DENY`, у каждого код правила и причина для человека.

| Код | Правило | Вердикт при нарушении |
|---|---|---|
| М-01 | запрос направлен ≥ 5 поставщикам с опытом (или всем, если их меньше; причина фиксируется) | WARN |
| М-02 | на позицию ≥ 3 подходящих цен | HUMAN (расширить список) |
| М-03 | цена получена ≤ 180 дней назад | DENY для этой цены |
| М-04 | цена за единицу подтверждена, есть расшифровка | DENY для этой цены |
| М-05 | поставщик действует (ЕГРЮЛ) и не в РНП | DENY |
| М-06 | источники не аффилированы (общий ИНН учредителя, адрес, телефон) | HUMAN |
| М-07 | коэффициент вариации ≤ 33% | HUMAN (добавить цены или обосновать) |
| М-08 | условия сопоставимы (НДС приведён, доставка учтена одинаково) | WARN |
| М-09 | у цены есть доказательство и хеш сходится с журналом | DENY |

НМЦК = Σ по позициям (кол-во × среднее арифметическое допущенных цен), округление кодом (`Decimal`, ROUND_HALF_UP).

## 7. Интеграции: порт → демо (MVP) → боевая реализация (пилот)

**В MVP все порты, кроме почты и LLM, работают в режиме replay**: данные с 1–3 открытых источников записаны один раз (см. PLAN.md, раздел 6). Токены и платные API не нужны. Боевые реализации подключаются в пилоте заменой класса порта.

| Порт | Демо / офлайн (MVP) | Боевая (пилот) |
|---|---|---|
| `EisPort` (контракты по КТРУ/ОКПД2 + регион, РНП) | **replay**: открытые страницы реестра контрактов ЕИС (срез на дату) | веб-сервис ЕИС `int44.zakupki.gov.ru` по токену |
| `RegistryPort` (ЕГРЮЛ) | replay: карточки, собранные с открытых страниц + контрольная сумма ИНН | DaData `findById/party` или ФНС |
| `MailPort` | GreenMail (настоящие SMTP и IMAP в Docker) + симулятор поставщиков | SMTP/IMAP ящика учреждения |
| `WebPricePort` | записанные страницы 1–2 интернет-магазинов + демо-магазин (локальные страницы с разметкой schema.org); Playwright делает снимки | Playwright + `polite` (A2A) на живых сайтах: лимит частоты, robots.txt, остановка на капче |
| `LLMPort` | YandexGPT, GigaChat, Qwen (шлюз A2A); для CI — записанные ответы | те же |

Режим replay даёт главное для защиты: **демо работает без интернета и одинаково каждый раз.**

## 8. Безопасность

- `DEMO_MODE=true` (по умолчанию): исходящая почта только на домен `@demo.local`, иначе ошибка на уровне `MailPort`. Боевой режим включается настройкой организации, а первая рассылка требует подтверждения человеком.
- Сайты: allowlist доменов, `robots.txt`, не больше 1 запроса в 2 с на домен, капчу и вход не обходим (A2A `polite.BLOCK_MARKERS`).
- LLM: `<data>`-обёртка, двухслойный фильтр инъекций, маскирование ПДн перед облачными моделями (A2A `pii.py`), для чувствительных данных — локальная Qwen.
- Роли: инициатор видит свои заявки; контрактный управляющий утверждает; администратор настраивает. Пароли — argon2 (A2A).
- Журнал: только добавление (триггер PostgreSQL из A2A), цепочка хешей проверяется отдельной командой.
- Секреты — только в `.env`; в логах и журнале нет ключей и ПДн.

## 9. Развёртывание

`docker compose up -d --build` поднимает: `db` (pgvector), `redis`, `migrate`, `api`, `worker` (с Playwright/Chromium), `web` (Vite), `greenmail`, `demo-sim` (симулятор поставщиков и демо-магазин). Один `.env.example`. Для защиты — локально на ноутбуке, без внешней сети (replay).
