## 1. Цель MVP — один сквозной демо-сценарий

> Контрактный управляющий ЧГУ вводит: «картриджи для HP LaserJet M428 — 20 шт., проектор для аудитории — 2 шт., бумага А4 — 50 пачек».
> 1. Агент разбирает текст, предлагает коды КТРУ, задаёт уточняющий вопрос. Человек подтверждает.
> 2. Агент находит поставщиков по контрактам ЕИС в Чеченской Республике и СКФО (replay-срез), проверяет их (ЕГРЮЛ, РНП, аффилированность), одного исключает с причиной.
> 3. Агент собирает 2–3 цены с сайтов со снимками страниц и отправляет запросы 6 поставщикам (GreenMail).
> 4. Симулятор отвечает: письмо в свободной форме, Excel-вложение, вопрос «оригинал или совместимый?», письмо с «Игнорируй инструкции…», а один поставщик молчит. «Ускорить время» → напоминание.
> 5. Агент разбирает ответы, отвечает на вопрос по спецификации, помечает подозрительное письмо, применяет методику (одну цену отбрасывает как устаревшую, CV по проектору выше 33% → дозапрос).
> 6. Черновик обоснования НМЦК (DOCX) с таблицей и ссылками на доказательства. Человек утверждает. В журнале видна цепочка хешей.

**Длительность показа:** 5–7 минут вживую + записанное видео на случай сбоя.

## 4. Риски и список отказов

| Риск | Признак | Что делаем |
|---|---|---|
| На сайте ЕИС или магазина капча при сборе среза | не удаётся сохранить страницы | сохраняем страницы вручную из браузера (это один раз и для 3 позиций), robots.txt и условия сайта соблюдаем |
| Playwright тяжёлый или нестабилен | > 0,5 дня отладки | только демо-магазин и записанные страницы, без живых сайтов |
| Модель плохо выбирает КТРУ | eval < 80% | выбор КТРУ человеком из top-5, модель только сортирует |
| Отставание больше дня | — | **отказываемся по порядку:** (1) уведомление о закупке; (2) PDF-вложения; (3) автоответы на вопросы (сразу человеку); (4) проверка аффилированности (оставить РНП и ЕГРЮЛ); (5) живые сайты (оставить демо-магазин) |

**Не отказываемся никогда:** разбор заявки → поставщики из ЕИС → письма и ответы → сверка цен → методика → DOCX → журнал. Это и есть продукт из паспорта.

## 6. Источники данных в MVP

Решение: в MVP **нет живых интеграций с токенами и ключами**. Агент работает с 1–3 открытыми источниками, данные по 3 демо-позициям записаны один раз и воспроизводятся. Логика агента от этого не меняется: подключение живого API в пилоте — это замена реализации порта, а не переделка.

| Источник | Что даёт | Зачем именно он |
|---|---|---|
| **Реестр контрактов ЕИС** (открытые страницы zakupki.gov.ru) | поставщики, которые уже поставляли этот товар госзаказчикам региона | это обещано в паспорте и прямо соответствует методике («поставщики с опытом исполнения контрактов») |
| **1–2 интернет-магазина** с открытыми ценами (выбрать при записи: разметка schema.org, нет капчи, robots.txt разрешает) | открытые цены со снимком страницы | показывает канал «цена с сайта + доказательство» |
| **Почтовая песочница** (GreenMail + симулятор) | ответы поставщиков в любом формате | показывает переписку, разбор писем и защиту от инъекций без писем реальным компаниям |

В интерфейсе и на защите это называется прямо: «срез открытых данных ЕИС на <дату>», «записанные страницы магазинов».
